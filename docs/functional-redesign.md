# TP Recorder 功能重设计（Session 1 审查稿）

状态：待用户审查确认

本稿只负责产品功能、行为契约和实现边界。当前没有修改 Android 源码，也没有编译、安装或部署。

## 1. 能力定义

TP Recorder 面向使用 DJI Mic Mini 发射器或兼容蓝牙麦克风的 Android 用户，提供“开始录音前确认真实外部蓝牙输入、锁屏后持续录音、分段保存、可回放和导出”的本地录音能力。

核心承诺不是“创建了一个音频文件”，而是：只有在系统确认 `AudioRecord.routedDevice` 为允许的外部蓝牙输入时才写入录音数据；蓝牙路由丢失时不得静默切回手机内置麦克风。

## 2. 附件内容与用户需求的优先级

压缩包中的 `README.md` 和 `metadata.json` 是 AI Studio 工程脚手架信息，包含 Gemini/API 等通用模板字段。它们不是本次产品需求，也不能覆盖用户已经明确的范围。

本项目以用户需求和已确认的设备路径为准：

- 录音源是 DJI Mic Mini 通过蓝牙直接连接手机，不改成 USB 接收器方案。
- 以本地录音为主，不引入云端上传、Gemini、账号或服务端依赖。
- 先完成功能重设计并审查，再进入 UI/UX、原型和 Android 原生开发。
- Android 开发 session 只写源码；不在本机编译、安装、部署或做性能验证。

## 3. 固定约束与不可破坏的不变量

### 3.1 外部输入安全门

生产录音模式只接受：

- `TYPE_BLUETOOTH_SCO`
- `TYPE_BLE_HEADSET`

必须拒绝并提示用户的输入：

- `TYPE_BUILTIN_MIC` 手机内置麦克风
- 有线耳机麦克风
- USB 音频设备
- A2DP 或 BLE Speaker 等通常不代表可录音输入的设备类型
- 无法从 `AudioRecord.routedDevice` 证明来源的默认路由

当前源码将 A2DP/BLE Speaker 也视为外部蓝牙输入，并且默认 `strictBluetoothOnly = false`，这与核心承诺冲突；后续实现必须收紧为单一的外部蓝牙安全策略。若未来需要手机麦克风测试模式，必须做成明确、隔离、带警告的开发/诊断模式，不得成为默认回退路径。

### 3.2 录音生命周期

- 录音由用户手动开始和停止。
- 锁屏、切出应用后继续录音依赖前台麦克风服务和常驻通知。
- 开始录音前必须完成权限、蓝牙状态、可用输入路由、存储空间和通知条件检查。
- 录音中持续验证当前路由；路由失效时立即停止当前写入，进入恢复等待，不继续把未知来源数据写入文件。
- 只要录音来源未被确认，就显示“等待外部麦克风”，而不是“录音中”。

### 3.3 文件完整性

- 每个正在写入的文件使用临时状态，只有编码器正常结束后才变为可见的已完成录音。
- 异常中断、存储不足、编码器失败产生的残片不得出现在正常录音库中；应保留可诊断状态或安全清理。
- 普通分段到时应关闭当前段并创建下一段；每一段都有序号、开始时间、结束时间、实际录音时长和来源路由。
- 录音时长按实际采集的音频时间计算，暂停、等待重连和初始化时间不计入录音时长。

## 4. 用户可见功能范围

### 4.1 首次使用与开始录音

1. 展示当前麦克风权限、通知权限、蓝牙开关和外部蓝牙输入状态。
2. 提供“打开系统蓝牙设置”入口，并提供重新扫描/刷新路由操作。
3. 开始按钮在未满足条件时不创建录音文件，而是指出缺少的条件和下一步操作。
4. 开始成功后明确显示设备名称、输入类型、采样率、格式、当前分段和已录音时长。

### 4.2 录音控制

- 开始录音
- 暂停录音
- 继续录音
- 停止并完成保存
- 锁屏后从通知停止录音
- 蓝牙断开后自动等待并重连；重连成功后创建新的分段，不覆盖旧段

暂停的产品语义：暂停时停止采集并封存当前段，恢复时创建新段。这样文件始终完整，暂停空白不会被伪装成有效录音时长。

### 4.3 录音库

录音库按“录音会话”分组，而不是只展示孤立文件。每个会话显示总时长、段数、开始时间、格式和来源设备；展开后查看每个分段。

每个已完成分段支持：

- 播放、暂停、拖动进度
- 分享
- 通过系统文件选择器导出到用户指定位置
- 删除并二次确认

播放和录音应互不破坏：开始新录音时停止播放；删除正在播放的文件前先停止播放器。

### 4.4 设置

首版只保留真实生效且与蓝牙输入兼容的选项：

- 编码格式：MP3 为默认；WAV 为无损诊断选项；M4A/AAC 仅在编码器能力确认后保留
- 比特率：根据格式显示可用范围
- 采样率：外部蓝牙路由默认 16 kHz；不展示会导致用户误解的无效组合
- 自动分段时长：15/30/60/120 分钟
- 默认外部蓝牙设备：自动或指定设备
- 存储占用与清理入口

当前 UI 中的“自动降噪与人声增益（AGC）”、立体声、保持屏幕常亮等字段没有完整接入录音服务。后续要么真正实现并验证，要么从产品设置中移除；不能保留看起来有效但实际不生效的开关。

所有设置都应持久化。应用重启后恢复配置，但正在录音时禁止修改会影响当前编码器和路由的参数。

## 5. 状态机

```text
IDLE
  -> PREFLIGHT       用户点击开始，检查权限/蓝牙/存储/通知
  -> WAITING_ROUTE   未发现合格的外部蓝牙输入
  -> STARTING        已发现路由，创建并启动 AudioRecord
  -> RECORDING       已通过 routedDevice 安全门并开始写入
  -> PAUSED          停止采集，当前分段已安全封存
  -> RECOVERING      录音中路由丢失，当前段结束，等待重新连接
  -> STOPPING        用户停止或系统终止，完成/清理当前段
  -> COMPLETED       本次会话至少有一个完整分段
  -> FAILED          权限、路由、编码器、存储或服务错误，给出可操作原因
```

关键转移规则：

- `WAITING_ROUTE`、`RECOVERING` 不得显示“录音中”，也不得写入 PCM。
- `STARTING` 只有在 `AudioRecord.STATE_INITIALIZED` 且 `routedDevice` 通过安全门后才能进入 `RECORDING`。
- `RECORDING` 每个采集循环都要能发现外部路由丢失并转入 `RECOVERING`。
- `PAUSED` 和 `STOPPING` 必须等待当前编码器释放完成后再刷新录音库。
- `FAILED` 不能自动伪装为 `IDLE`；用户需要看到最后一次失败原因和重试入口。

## 6. 数据与文件契约

建议引入“会话 + 分段”的最小领域模型：

### RecordingSession

- `sessionId`
- `startedAt`
- `endedAt`
- `status`: `RECORDING / PAUSED / RECOVERING / COMPLETED / FAILED`
- `sourceDeviceName`
- `sourceDeviceType`
- `format`
- `sampleRate`
- `totalDurationMs`
- `segmentCount`
- `lastError`

### RecordingSegment

- `segmentId`
- `sessionId`
- `sequence`
- `startedAt`
- `endedAt`
- `durationMs`
- `filePath`
- `bytes`
- `status`: `WRITING / READY / FAILED`
- `verifiedRouteType`

首版可以继续使用应用专属外部 Music 目录和 FileProvider，但必须增加完成状态/会话索引；不依赖文件名猜测时长，也不把“文件存在”当成“录音完成”。

## 7. 现有工程审查结果

可以复用的基础：

- 已有 `AudioRouteController`、`RecordingService`、MP3/WAV/AAC 编码器和前台服务结构。
- 已有 `AudioRecord.routedDevice` 检查、锁屏录音所需的前台服务声明和唤醒锁。
- 已有录音库播放、分享、删除和 Compose 测试截图骨架。

必须在 Android 开发 session 修复的功能缺陷：

1. `RoutePolicy` 放行 A2DP/BLE Speaker，可能把非录音输入误判为安全外部麦克风。
2. 默认 `strictBluetoothOnly = false`，可能允许手机内置麦克风回退。
3. 已配对蓝牙设备使用负数伪 ID，但选择逻辑只按真实输入设备 ID 查找，用户选择的设备可能没有真正生效。
4. 录音循环只在创建 `AudioRecord` 时检查路由，录音过程中没有逐段/逐循环路由安全门。
5. 暂停时以墙上时钟累计时长，暂停时间会被计入录音时长。
6. 停止后立即刷新录音库，可能早于编码器完成和文件关闭。
7. 异常文件没有明确的临时/完成状态，残片可能被录音库展示。
8. 设置状态只在内存中存在，应用重启后丢失。
9. AGC/降噪、立体声、保持屏幕常亮等配置没有完整传入或应用。
10. 当前 `README.md` 仍是 AI Studio/Gemini 脚手架文档，不能作为本地蓝牙录音产品说明。
