# TP Recorder UI/UX、Logo 与排版设计稿（Session 2 审查稿）

状态：待用户敲定

本稿是基于 Session 1 功能契约的视觉与交互设计，不修改 Android 源码，不编译，不安装，不做设备验收。后续原型和原生开发必须以本稿确认版为准。

## 1. 设计定位

### 设计一句话

TP Recorder 是一台“随身录音仪”的 Android 控制台：用户打开它，先确认真实的外部蓝牙麦克风，再开始采集；所有重要信息都靠层级、数字和状态说清楚，不靠装饰性动画。

### 目标用户与核心任务

- 用户：使用 DJI Mic Mini 或兼容蓝牙麦克风的个人创作者、采访者、现场记录者。
- 第一任务：确认现在录到的是哪一个外部麦克风。
- 第二任务：一键开始、暂停、恢复、结束并保存。
- 第三任务：找到最近一次录音并播放/导出。

### 视觉气质

技术、克制、可靠、略带设备感。不是“AI 工具紫色渐变”，不是软拟物，也不是黑客终端。页面要像一个经过校准的现场录音仪表盘。

## 2. 视觉系统

### 2.1 色彩

采用暖灰纸面 + 墨色文字 + 单一焦糖橙品牌色。绿色、琥珀色、红色仅用于状态语义，不能作为装饰色大面积铺开。

| 语义 | 设计值 | 用途 |
| --- | --- | --- |
| Paper | `oklch(96% 0.012 85)` / `#F5F2EB` | 页面背景 |
| Surface | `oklch(99% 0.006 85)` / `#FCFBF7` | 主要面板 |
| Ink | `oklch(22% 0.018 155)` / `#28302D` | 标题、关键数字 |
| Ink secondary | `oklch(46% 0.018 155)` / `#69716C` | 辅助信息 |
| Rule | `oklch(86% 0.014 85)` / `#D9D5CA` | 分隔线、输入边界 |
| Brand | `oklch(56% 0.145 48)` / `#BE6A36` | 主按钮、选中态、品牌标记 |
| Connected | `oklch(53% 0.105 155)` / `#397A5B` | 已确认外部蓝牙输入 |
| Waiting | `oklch(63% 0.12 78)` / `#B88427` | 等待连接、恢复中 |
| Error | `oklch(52% 0.12 28)` / `#B6534D` | 错误、拒绝写入、存储不足 |

规则：不使用紫色主色；不使用渐变文字；阴影极轻且偏暖；连接状态同时显示图标、文字和颜色，不能只靠颜色区分。

### 2.2 字体与排版

建议将字体作为 Android 本地资源打包，避免运行时依赖网络：

- UI 正文：`IBM Plex Sans`，中文回退 `Noto Sans CJK SC`。
- 标题/品牌：`Bricolage Grotesque`，中文回退 `Noto Sans CJK SC`。
- 时间、分贝、采样率、文件名：`JetBrains Mono`，中文回退系统等宽字体。

字体层级：

| 层级 | 尺寸 | 字重 | 用途 |
| --- | ---: | ---: | --- |
| Display timer | 44/48sp | 600 | 录音时长，使用等宽数字 |
| Page title | 26/30sp | 700 | 页面标题 |
| Section title | 18/22sp | 700 | 区块标题 |
| Body | 16/24sp | 400 | 正文和说明 |
| Label | 12/16sp | 600 | 状态标签、辅助字段 |
| Technical | 12/18sp | 500 | 文件名、设备信息、dBFS |

所有数字启用等宽数字；正文最小 14sp，主要说明保持 16sp；标题用句首字母式中文，不使用满屏英文大写标签。

### 2.3 间距、形状与层级

- 基础间距采用 4dp 倍数：4、8、12、16、24、32、48dp。
- 页面水平边距：手机 20dp；平板/横屏最大内容宽度 720dp。
- 主要面板圆角 16dp；内部控件 10/12dp；按钮 12dp。
- 不把每一块内容都包成卡片：主控制台使用一个面板，次要信息使用分隔线和留白。
- 触摸目标不小于 48dp；图标按钮必须有可读的 contentDescription。
- 阴影只用于主控制台和底部操作区，避免当前 20/24/28dp 圆角 + 阴影重复堆叠。

## 3. Logo 设计

### 3.1 Logo 概念：Signal TP

不使用通用麦克风剪影。标志由一个“垂直捕获线”和一个“被切开的信号波形”组成：

- 左侧直线形成 `T` 的主轴。
- 右侧半环形成抽象的 `P`，开口处切入一条短波形缺口。
- 缺口不是装饰，而是代表“输入正在被确认”。
- 图形整体落在 1:1 圆角方形中，适合启动图标、通知栏和空状态。

### 3.2 Logo 版本

1. App icon：暖纸色底，墨色 Signal TP，右上角一个焦糖橙小圆点。
2. App bar：Signal TP 图形 + `TP Recorder` 字标，字标使用 Bricolage Grotesque 半粗体。
3. 单色版本：通知栏、深色系统背景和无障碍高对比度场景只保留墨色/白色图形。
4. 小尺寸版本：24dp 以下隐藏波形缺口，只保留 `TP` 几何骨架，避免缩小后糊成麦克风图标。

### 3.3 Logo 禁止项

- 不使用渐变。
- 不使用麦克风、耳机、声波三件套的通用素材组合。
- 不把 `M` 作为当前源码中的临时头像标记。
- 不在不同页面替换不同 Logo 形态。

## 4. 页面结构

### 4.1 录音页：Record

页面顺序：


```text
┌──────────────────────────────────┐
│ Signal TP   TP Recorder      ⋯  │  顶部栏
│                                  │
│ 外部输入                         │  区块标题
│ [●] DJI Mic Mini                 │  路由状态面板
│     蓝牙 SCO · 已确认可录音      │
│     [刷新路由] [打开蓝牙设置]    │
│                                  │
│          00:00:00                │  大号等宽计时器
│          已准备好                │  当前状态
│     ─────实时电平─────           │  波形与 dBFS
│                                  │
│ [结束并保存]                     │  录音中主操作
│ [开始录音]       [设置]          │  空闲主操作区
│                                  │
│ 本次录音                         │  会话摘要
│ MP3 · 16 kHz · 30 分钟自动分段  │
│ 设备存储剩余 7.3 GB              │
└──────────────────────────────────┘
```

状态变化：

- 未连接：顶部状态为“未连接外部麦克风”，主按钮显示“连接后开始”，按钮禁用但提供“打开蓝牙设置”。
- 已连接待录音：显示“DJI Mic Mini · 已确认可录音”，主按钮为焦糖橙“开始录音”。
- 初始化：主按钮进入 loading，文案为“正在确认输入”，不显示“录音中”。
- 录音中：计时器和波形进入活动态；主按钮为“结束并保存”，旁边显示“暂停”。
- 已暂停：计时器冻结，状态为“已暂停 · 当前分段已保存”；按钮为“继续录音”。
- 路由恢复：状态为“蓝牙输入已断开 · 等待重新连接”，不写入数据，保留“停止并保存已有分段”。
- 错误：状态面板显示原因、影响和下一步操作；主按钮为“重新尝试”，不使用模糊的“发生错误”。

录音页的视觉焦点只有两个：当前真实输入源、当前录音控制。存储和格式降为摘要，不与计时器争夺焦点。

### 4.2 会话库：Sessions

不再把所有分段平铺成一长串文件卡片，改为会话列表：

```text
会话                                    [筛选] [刷新]

今天 · 2 个会话
┌──────────────────────────────────┐
│ 采访现场                          │
│ 09:42 · 34:12 · 2 个分段 · MP3   │  [播放]
│ DJI Mic Mini · 16 kHz             │
│                         [导出] [⋯]│
└──────────────────────────────────┘

昨天 · 1 个会话
┌──────────────────────────────────┐
│ micmini_20260822_083000           │
│ 08:30 · 12:04 · 1 个分段 · MP3   │
└──────────────────────────────────┘
```

交互：

- 点击会话展开分段；播放条只在当前会话内展开。
- 默认展示最近 30 天；下拉刷新不遮挡当前播放进度。
- 导出是明确动作，调用系统文件选择器；分享使用系统分享面板。
- 删除采用“删除 + 可撤销提示”，不可逆清理才使用二次确认。
- 空状态直接引导：“连接 DJI Mic Mini 后，第一段录音会出现在这里。”
- 读取失败、文件不完整和文件不存在都有独立状态，不与普通空列表混淆。

### 4.3 设置页：Settings

设置页改为分组列表，不再使用过长的堆叠式底部弹窗：

1. 输入设备：当前设备、自动选择、重新扫描、打开系统蓝牙设置。
2. 录音格式：MP3 默认、WAV 诊断；每个选项显示适用场景。
3. 音频质量：采样率、比特率；无效组合隐藏而不是允许选择后无效。
4. 自动分段：15/30/60/120 分钟。
5. 存储：目录、剩余空间、清理不完整文件、导出说明。
6. 后台录音：前台服务说明、电池优化设置引导、通知权限状态。
7. 关于：版本、隐私说明、蓝牙兼容性说明。

设置底部固定一个“完成”动作，但已保存的配置不依赖点击完成才生效；点击只是关闭页面。

### 4.4 首次使用页：Connect

只在必要时出现，不做长 onboarding：

1. “连接你的外部麦克风”。
2. 说明：在系统蓝牙设置中连接 DJI Mic Mini 发射器。
3. 按钮：“打开蓝牙设置”。
4. 返回后自动扫描，显示“正在确认可录音输入”。
5. 成功后进入录音页；失败时解释“系统没有把该设备暴露为可录音输入”，不承诺 Android 一定可以强制绕过系统路由。

## 5. 组件与状态规范

### Route status panel

- 已确认：绿色圆点 + Bluetooth 图标 + “已确认可录音”。
- 已配对但不可录音：琥珀色图标 + “已配对，等待系统提供输入”。
- 未连接：灰色图标 + “未连接外部麦克风”。
- 被拒绝：红色警告图标 + “当前不是外部蓝牙输入，未写入文件”。

### Waveform / meter

- 空闲：静态细线，不循环呼吸。
- 录音：仅波形和电平随采样变化；不使用彩虹渐变。
- 接近削波：电平条转红，并显示“电平过高”。
- 静音：保留基线，显示“未检测到明显输入”，不要误判为路由失败。

### Primary controls

- 空闲：一个主按钮“开始录音”。
- 录音中：一个危险色按钮“结束并保存”，一个次按钮“暂停”。
- 暂停：一个主按钮“继续录音”，一个次按钮“结束并保存”。
- 恢复中：主按钮“停止并保存已有分段”，次操作“重新扫描”。
- 所有按钮最小 48dp 高度，按下时只做轻微位移/颜色反馈，不做弹跳。

### Error copy formula

统一使用三段式：发生了什么 → 影响是什么 → 下一步做什么。

示例：

> 蓝牙输入已断开。当前没有写入手机麦克风，已有分段仍然安全。请重新连接 DJI Mic Mini，或停止并保存本次录音。

## 6. 动效与可访问性

- 动效只服务于状态确认：按钮按下、路由状态切换、波形采样、会话展开。
- 页面首次进入不做整页卡片逐个淡入。
- 录音状态不使用连续脉冲光环；只用静态“正在录音”标记和真实波形。
- 动效时长：按下 100ms，控件切换 180–220ms，页面/面板展开 250–300ms。
- 支持 Android 动画缩放与无障碍减弱动效设置；减弱模式只保留即时颜色和状态更新。
- 颜色之外必须有文字、图标或形状差异。
- 所有触控项 48dp 以上；错误状态可被 TalkBack 读到；计时器不每帧播报，只在状态切换时更新无障碍语义。

## 7. 响应式页面稿

### 320dp

- 单列布局。
- 顶部标题缩短为 `TP Recorder`，右侧只保留一个设置入口。
- 路由按钮采用上下排列，避免设备名被截断。
- 主按钮全宽；设置摘要采用两列标签值。

### 375dp / 414dp

- 保持单列，扩大计时器与波形留白。
- 操作区为“主按钮 + 两个次操作”结构。
- 会话列表每行最多两行信息，文件名使用中间省略。

### 600–768dp

- 录音页采用两列：左侧路由/录音控制，右侧实时波形/会话摘要。
- 设置页使用双栏分组，但不把每个设置项做成独立卡片。
- 会话详情可在右侧展开，避免全屏跳转。

## 8. 现有 Compose 结构的改造映射

保留现有功能边界，不删除工作逻辑；后续原生开发时按以下方式替换视觉层：

- `MainScreen.kt`：改为 Record / Sessions / Settings 的页面壳和导航状态。
- `RouteStatusCard.kt`：重做为 Route status panel，修正文案“输出”误用为“输入”。
- `WaveformVisualizer.kt`：保留真实波形计算，移除紫色渐变和空闲循环装饰。
- `RecordingsSheet.kt`：从平铺文件列表改为会话分组 + 分段展开。
- `SettingsDialog.kt`：从超长底部弹窗改为设置页/分组页面。
- `Color.kt`、`Theme.kt`、`Type.kt`：替换为本稿语义色、字体和间距令牌。
- Logo 资源：新增 Signal TP 的矢量图标、单色通知图标和自适应启动图标。

本 session 不删除旧文件，不改路由、录音服务、播放器和仓储实现。

## 9. 原型前验收清单

进入 Session 3 前需确认：

1. 是否采用“Signal TP”而不是通用麦克风 Logo。
2. 是否确认暖灰 + 墨色 + 焦糖橙的整体方向，彻底移除紫色主视觉。
3. 是否确认主页面分成“外部输入 → 录音控制台 → 会话摘要”三层。
4. 是否确认录音库按会话分组，而不是平铺文件卡片。
5. 是否确认状态文案优先于动画，路由断开时明确显示“未写入手机麦克风”。

确认后进入 Session 3：把本稿转成交互原型，覆盖首次连接、开始录音、暂停、断连恢复、完成保存、会话播放和导出流程。
